# Dust II 战术布局修正

原因：原配置将 T 出生放在 A 小、CT 出生放在 B2，A 点偏离实际平台，B 标记在箱后较深处；
低层 `outsideGround` 黑名单还会误杀从通路能走到的地面。此次保留原建筑，重新配置玩法区域。

以下为原存档坐标，蓝图坐标需减去 origin `[52, 13, 42]`，再由竞技场中心平移：

| 区域 | 原存档坐标 | 地形核验 |
| --- | --- | --- |
| T1～T5 | `(-2, 18, z)`，z 为 24、27、30、33、36 | 匪家高地，y17 为完整 cut_sandstone，脚/头为空气，朝东 |
| CT1～CT5 | `(x, 11, 39)`，x 为 88、91、94、97、100 | 中路桥下低层道路，y10 原沙子固定为砂岩，脚/头为空气 |
| A 下包标记 | `(103, 18, 88)` | 原图唯一红色混凝土地面标记，位于 A 平台 |
| A 安装区 | min `(99, 17, 78)` / max `(115, 20, 93)` | 覆盖平台，不包含旧 A 小出生位置 |
| B 下包标记 | `(112, 15, -2)` | 默认箱体前方，上半砂岩台阶提供完整支撑面 |
| B 安装区 | min `(104, 14, -12)` / max `(119, 17, 5)` | 覆盖 B 庭院平台，避免只标到箱后深处 |
| T 购买区 | min `(-4, 16, 21)` / max `(14, 21, 39)` | 包含五个匪家高地出生点 |
| CT 购买区 | min `(84, 10, 36)` / max `(103, 14, 45)` | 包含五个低层出生点 |

原图没有提供有效的阵营/包点命令配置，标牌也未提供战术文字。定位依据为完整地形、
A 原生红色地标、默认箱体和主通道连接；两次独立审计交叉核对了出生净空、支撑和路线。
`tools/audit_mygo_map.py` 从每个出生检查到两个包点的近似步行路线，不能替代原版碰撞实服验证。

`playBounds` 覆盖完整建筑范围，水平外扩两格、上方保留八格空间；原 7,377 列的隐藏黑名单已移除。
越出这个外围框或进入虚空只触发最近安全点救援，不扣血、不计阵亡。安全点仅在实际落地且
身体无碰撞、脚下有支撑时更新。

原图的 61 个按钮只有装饰用途，没有碰撞。按钮的原版客户端预测会修改本地 powered 状态，
并产生与左键无法可靠区分的挥手包；运行时使用同一 BlockState 的原版 block_display 保留外观，
位置改为空气，不改变通路碰撞。这不改变客户端资源包或要求客户端 Mod。
展示实体带有每场专属所有权标签：区块重载时按 UUID 更新对象引用，结束时注销所有权；
未加载区块中的旧实体日后重载时会自动丢弃，避免重复开局累积装饰。
